# Contributing to AI-Powered Study Assistant

Thanks for your interest in contributing to **AI-Powered Study Assistant**!

This project is maintained by **Yogesh Sheoran** and is open to improvements, bug fixes, new features, and documentation updates.

Please read these guidelines before opening an issue or pull request.

---

## 💡 Types of Contributions Welcome

* 🐞 Bug fixes and robustness improvements
* ✨ New features that improve the learning experience
* 🧹 Code cleanup, refactoring, and performance improvements
* 📚 Documentation updates, including README, user guides, and examples
* 🎨 UI/UX improvements
* ⚡ Performance improvements

If you are not sure whether an idea fits the project, feel free to open an issue first for discussion.

---

## 🪜 How to Contribute

### 1. Fork the Repository

Click the **Fork** button on GitHub to create your own copy under your GitHub account.

### 2. Clone Your Fork

```bash
git clone https://github.com/<your-username>/AI-powered-Study-Assistant-main.git
cd AI-powered-Study-Assistant-main
```

### 3. Create a Feature Branch

```bash
git checkout -b feature/short-descriptive-name
```

### 4. Set Up the Project

Create and activate a virtual environment:

```bash
python -m venv venv
```

Activate it on Windows:

```bash
venv\Scripts\activate
```

Install the required dependencies:

```bash
pip install -r requirements.txt
```

Add your Gemini API key using `.env` or the appropriate deployment secret configuration.

**Never commit API keys, passwords, or other sensitive information.**

### 5. Make Your Changes

* Keep the code style consistent with the existing project.
* Add comments and docstrings where useful.
* Keep changes focused and easy to review.
* Update the documentation when project behavior changes.

### 6. Run and Test Locally

Start the application:

```bash
streamlit run main.py
```

Make sure your changes work correctly across:

* 🧠 Explainer
* 📄 Summarizer
* 🧩 Quizzer

Also make sure existing functionality is not broken.

### 7. Commit Your Changes

```bash
git add .
git commit -m "feat: short description of change"
```

### 8. Push Your Branch

```bash
git push origin feature/short-descriptive-name
```

### 9. Open a Pull Request

Go to your fork on GitHub and create a **Pull Request**.

Clearly describe:

* What you changed
* Why you made the change
* How you tested it
* Any screenshots for UI changes

---

## ✅ Pull Request Expectations

To keep the project maintainable:

* Keep PRs focused and reasonably small.
* Make sure the application runs without errors.
* Test your changes before submitting a PR.
* Be responsive to review comments.
* Keep commits clear and meaningful.

### ❌ Do Not Include

* API keys
* Passwords
* Credentials
* `.env` files containing secrets
* Unrelated large refactors
* Unnecessary generated files

PRs that do not meet these basic requirements may be requested for changes before merging.
